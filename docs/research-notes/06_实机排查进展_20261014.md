# 实机排查进展（2026-10-14 22:33，Windows）

**尚未调通深度测距。已解决 USB 枚举失败和未安装驱动；等待安装后重启，再验证 SDK 识别及实际深度帧。** 本文补充先前资料，不将硬件 ID 当作机身型号的最终证明。

## 已验证的变化

1. 用户单独拔下所称 D2 相机，`2BC5:0505` RGB、`05E3:0610/0620` 两个 USB 集线器、`USB\\SET_ADDRESS_FAILURE` 代码 43 设备一起消失。由此确认代码 43 属于相机连接链路。
2. 用户使用同一根线，改接另一个电脑本机 USB 口：代码 43 消失，深度设备开始以 `USB\\VID_2BC5&PID_060D` 枚举，名称 `Orbbec(R) Astra(TM)`，当时错误码 28（缺驱动）。这是换口后观察到的结果，尚不能据此断言原接口永久损坏。
3. 安装官方 `SensorDriver_V4.3.0.22.exe`，用户完成管理员确认和安装向导。安装前已核对官方发布包的 SHA-256。

官方驱动 ZIP 实测 SHA-256：`009ACCC9449202855EDA35235EDAD5DAB3ABBB2840ADD231661309892F985F05`。外层安装 EXE 未签名；安装后的驱动目录 `C:\Program Files\Orbbec\ASTRA` 中 `obdrv4.cat` 签名状态 Valid，签名者 Microsoft Windows Hardware Compatibility Publisher。

4. 安装后 Windows 显示 `ORBBEC Depth Sensor`、Orbbec 类、状态 OK、错误码 0。驱动 `oem56.inf` / `obdrv4`，版本 4.3.0.22，服务 Running。
5. 用户拔下等待约 5 秒后插回成功的同一接口，状态仍正常。设备属性 `IsRebootRequired=False`，但厂商安装说明明确要求重新插拔及重启，故重启仍是待验证步骤，并不保证重启一定解决。
6. 原 OpenNI 2.3.0.86-beta6 初始化成功，orbbec.dll 确实加载，但设备数仍为 0。启用诊断日志、等待枚举、使用纯英文路径复测，以及尝试打开系统返回的设备接口 URI，均未成功打开相机。
7. 从官方发布页下载 OrbbecSDK v1.10.37 Windows x64，运行原厂 `hello_orbbec.exe`，仍返回 `Device not found!`。日志能列出深度与 RGB 接口，但没有形成可用设备。原目录和纯英文目录结果一致。
8. 通过 Windows CreateFile 打开实际深度接口（分别零访问、读、读写句柄，未发送设备控制请求）均成功，说明不是简单的接口打开权限不足。没有据此证明固件通信正常。

## 型号尚需核验

官方 ROS USB 规则将 `2BC5:060D` 标注为 Astra Pro Plus，`2BC5:0505` 标注为 RGB UVC。这与购买时所称 D2 不一致。机身标签、卖家版本、SDK 实际型号和固件版本仍需确认；目前无法据此判定错发或假货，也不应刷 Astra 固件或直接套用 D2 的量程和分辨率。
