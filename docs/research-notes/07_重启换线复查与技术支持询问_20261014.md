# 重启、换线及管理员权限复查（2026-10-14）

**结论：深度测距尚未调通。系统驱动正常，两个官方 SDK 都无法枚举为可用相机。** 不能仅凭当前结果判定相机损坏，也不能保证更换 SDK 一定解决。下一步需要厂商确认该具体硬件/固件批次的适配软件，或在有验证软件的另一台电脑上交叉检测。

## 实物标识

用户抄录的标签内容：`MX6000`、`TornadoD2_3.0.16`、`D2_LABEL_SERIAL`。这些是用户提供的标签文字，尚未通过相机 API 读取并确认其字段含义。

MX6000 是奥比深度计算芯片的名称，不是唯一相机型号。不能仅凭 `2BC5:060D` 在官方 ROS 规则中对应 Astra Pro Plus，就推定本机实物型号；应同时提供 TornadoD2 标签给厂商核验。

## 本轮复查结果

| 对照 | 结果 |
|---|---|
| 安装驱动后重启 Windows | 深度和 RGB 均为 OK，OpenNI 仍枚举 0 台 |
| OrbbecSDK v1.10.37 原厂 hello_orbbec.exe | `Device not found!`；日志可列出 RGB 和深度 USB 接口 |
| 换另一根 USB 2.0 数据线，保持同一本机端口 | 确认 SuperSpeed 集线器消失，深度设备改挂 USB 2.0 集线器；状态 OK，无代码 43 |
| USB 2.0 下 OpenNI 2.3.0.86-beta6 | 初始化成功、驱动插件加载，枚举 0 台；取帧脚本在设备数量检查处停止 |
| USB 2.0 下 OrbbecSDK v1.10.37 | 同样 `Device not found!` |
| 管理员权限运行上述两个测试 | 已确认 Elevated=True，结果相同；日志完整结束 |

原 USB 3.0 连接深度实例为 `USB\VID_2BC5&PID_060D\6&1C51E28A&0&2`。换 USB 2.0 线后的实例为 `USB\VID_2BC5&PID_060D\6&B91EBB1&0&1`。驱动仍为 Orbbec 4.3.0.22。

另使用 SDK 附带的 libusb 库只读查询了 USB 描述符：USB 3.0 状态下能看到深度 VID/PID，打开返回 -12（不支持）。由于设备绑定的是 Orbbec 自有 obdrv4 驱动，不能据此认定设备损坏或要求强制改装 WinUSB；本轮没有替换为 WinUSB。

没有取得深度帧、中心距离、固件 API 版本或标定参数。没有执行固件升级、恢复出厂、关闭安全软件、轮椅运动控制或 RDK X5 部署。

## 原始证据

位于 `<PRIVATE_WORKSPACE>\测试\D2相机_20261014`：

- `重启后复查.json`：启动时间、标签和 USB 状态。
- `USB2换线后状态.json`：换线后的设备实例及状态。
- `elevated_probe.txt`：管理员身份确认与 OpenNI 枚举结果。
- `elevated_sdk_stdout.txt`、`elevated_sdk_stderr.txt`：管理员运行官方示例的输出。
- `安装驱动后设备状态.json`：驱动版本、签名和初次安装状态。
- `probe_depth.py`：取帧程序已准备，当前未通过设备枚举阶段，不应视作已验证的测距方案。
- `probe_usb_descriptor.py`、`probe_elevated.ps1`：本轮诊断脚本；后者会在 15 秒后结束自己启动的官方示例，避免其等待 ESC 而长期占用相机。
