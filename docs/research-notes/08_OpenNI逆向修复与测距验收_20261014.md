# D2 OpenNI 逆向修复与测距验收

2026-10-14，当前 Windows 电脑、本机 USB 口、用户更换的 USB 2.0 数据线。此记录更新 06、07 的“无法取深度”结论；历史排查记录仍保留。

## 结论与启动

已恢复 D2 深度和红外取流，彩色接口也单独取图成功。推荐默认深度 400×640、30 fps，输出为 SDK 的毫米深度。尚未进行 RGB/深度同步、彩深配准、点云几何精度、全量程或长时间稳定性验收。

- 启动 D2 深度测距（原始归档项）：白框对应中心 21×21 像素，显示其中非零深度的中位数。
- 启动 D2 红外预览（原始归档项）：640×400、GRAY16，数值为原始强度，不是距离。
- 启动高分辨率深度（原始归档项）：800×1280，本机设备报告 5 fps；不承诺官网参数中的 30 fps。

每次只运行一个入口；关闭图像窗口即可正常停止并保存结果，入口还设有帧数上限。深度/红外结果自动保存到 `测试/D2相机_20261014/depth_时间戳` 或 `ir_时间戳`，含逐帧 JSON 和最后一帧 NumPy 原始数组。彩色独立诊断脚本为 probe_rgb.ps1（原始归档项）。

本机启动器依赖 Codex 缓存中的 Python 3.12、NumPy/Pillow/Tk，以及 Microsoft Office 安装目录中的 x64 VC++ 2013 CRT。SDK 从已归档 ZIP 加载。普通运行不依赖 Frida；迁移电脑需重新处理运行库和路径，不能仅复制 CMD 文件。

## 枚举失败根因与修复

官方 OpenNI 2.3.0.86 beta6 能初始化、加载 orbbec.dll，但其枚举名单的 45 个 PID 不包含本机 060D。Frida 对自己启动的 Python 探针跟踪 `xnUSBEnumerateDevices`，调用序列与 PE 表一致，未尝试 060D。因此驱动正常后，仍返回设备数 0。

对照：原始 SDK 设备数 0；同一硬件、同一 DLL，只在自身进程内把表的首项 `2BC5:0300` 改为 `2BC5:060D`，设备数变为 1，并成功读回型号、启动深度流。此结果支持“枚举遗漏是当前取流阻塞点”。它不证明所有固件功能都兼容。

- SDK：官方 `OpenNI_2.3.0.86_202210111950_4c8f5aa4_beta6_windows_x64.zip`。
- orbbec.dll SHA-256：`bd08e87378eba3342f892c5d9cf00af1dfbf674ef46cec3812ebec0d669d1245`。
- 表文件偏移 `0x9D590`，运行时 RVA `0x9F590`，由模块实际基址定位，适应地址随机化。
- 修改前强制核对整个文件哈希和原始首项；不匹配即报错停止。修改仅持续至当前进程退出。
- 磁盘 DLL 未修改、USB 描述符未伪装、固件未刷写、系统驱动未被补丁替换。该专用进程中首项 0300 被占用，不用于多型号并行枚举。

执行代码：probe_openni.py（原始归档项） 的 `--d2`；取流与预览：probe_depth.py（原始归档项）。

证据：reverse_openni_findings.json（原始归档项）、运行时枚举跟踪（原始归档项）。Orbbec SDK v1.10.37 的独立静态检查也发现相关枚举表遗漏本机 PID，记录在 `测试/D2相机_20261014/reverse_sdk_v1/`；没有为它实施第二套补丁。

按用户要求使用 reverse-engineer-anything 技能工作流；本机 REA MCP/反编译引擎不可用，实际证据来自 PE/Capstone 静态分析、Frida 运行时跟踪及官方 C API 实测，不冒称 REA 工具分析结果。

## 尺量核验及失效反例

中心值为 21×21 区域内非零像素中位数；不加偏移修正，不按尺量值反推校准系数。

| 用户尺量 | 采集 | 中心读数 | 结论 |
| --- | --- | --- | --- |
| 570 mm | 300 帧 / 10.032 秒 | 每帧 571 mm | 本点差 +1 mm |
| 1000 mm | 300 帧 / 10.031 秒 | 993–998 mm，中位数 998 mm | 本点中位数差 −2 mm，中心非零占比最低约 67% |
| 1670 mm | 90 帧 / 3.062 秒 | 每帧 182 mm | 超过官方 1300 mm 上限，读数错误，不作为有效距离 |

汇总与原始目录：ruler_validation.json（原始归档项）。这是用户现场尺量的两点合理性核验，不是实验室标定或全量程精度保证；轴向深度、量尺起点、目标角度都会影响比较。

预览将 300–1300 mm 之外的像素涂黑；中心标记 `out_of_range` 或 `no_data` 时不可使用。`in_nominal_range` 只表示数值处于标称范围，**不能保证远处目标不会产生落入范围内的错误匹配**。JSON 的 `valid_fraction` 历史字段仅表示非零占比，并非可信深度占比；167 cm 反例中中心非零占比为 100%，仍是错值。不能用“非零”作为安全感知有效性的充分条件。

## 官方资料适用性与下一步边界

官方单目结构光 OpenNI 通用资料确实适用于这台设备的深度/红外 API 和 D2 数据格式，但通用发布包的枚举表未覆盖本机 PID。“资料通用”不能等同于每个发布包开箱识别所有旧固件。

- [D2 官方参数](https://www.orbbec.com.cn/index/product/info.html?cate=38&id=31)：近距离结构光、标称 0.3–1.3 m。
- [官方 OpenNI API](https://github.com/orbbec/OpenNI_SDK/blob/a640cb3724f323dc83d410d0550b5d504894db8a/Doc/English/0400_API.md)：D2 深度 400×640 / DEPTH_1_MM、IR 640×400 / GRAY16、D2 Packed 10-bit。
- [官方 SDK 发布页](https://github.com/orbbec/OpenNI_SDK/releases/tag/v2.3.0.86-beat6)：本次验证的 Windows x64 版本来源。

未连接或部署 RDK X5。ARM64 二进制布局与 Windows 不同，不能直接复用 RVA 补丁。没有验证强光、黑色/反光目标、全视场精度、长期掉帧或应用级故障降级；当前成果用于近距离测距预览和后续接入开发，不具备轮椅安全避障验收结论。
